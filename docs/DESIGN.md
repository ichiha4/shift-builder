# UI・UXの設計

2026-10-17更新。高校生・大学生・フリーターが、自分のシフトと給与を簡単に記録するアプリです。主な画面はホーム・シフト・給与に絞ります。

## 最優先：日付を選択 → テンプレートをタップ

カレンダーで追加する日を選び、テンプレートを1回タップすれば保存まで完了します。追加のフォームや保存ボタンは挟まず、選択日を維持するため、そのまま別の日にも続けて入力できます。

- 「テンプレートを作成」で、日付なしの勤務先・時間・時給・休憩などを保存。同じ勤務先で複数の時間帯を持てる。
- 作成だけでは実際の勤務・給与予定を増やさず、保存後は新しいテンプレートまで横スクロールする。手入力した勤務履歴も再利用できる。
- 連続登録でタップ対象が動かないよう、勤務先・時間を基準に安定した順序で表示。
- 5件を超えたパターンも横スクロールで選択可能。長押しで使わないものを非表示にできる。
- テンプレート欄は見出しと作成ボタンを1行にまとめ、文字拡大で収まらない場合は縦に並べる。作成ボタンは背景に合わせた細い輪郭の角丸ボタンとし、保存済みパターンの管理はその横に置く。
- 横スクロールのカードはライトモードで白と淡いグリーン、ナイトモードで黒と深いグリーンを使い分ける。薄い光、細い輪郭、短い影で奥行きを出す。勤務先の下に出勤・退勤を分けて並べ、罫線の下へ時給や休憩をまとめる。追加済みはグリーンの文字とチェック、重複はアンバーの文字と記号で伝える。明るい背景では濃い文字・記号、暗い背景では明るい文字・記号を使う。数字は標準書体の通常の太さを維持する。押したときだけ小さく反応し、「視差効果を減らす」では縮小を行わない。
- 追加済みのチェックと触覚フィードバックで保存を伝える。
- 重なる勤務を無効化し、保存直前にも再確認。異なる勤務先・日跨ぎも検証。
- 明示的に保存したテンプレートは、そのパターンの全勤務を削除しても残る。保存していない履歴由来の候補は、履歴がなくなると消える。
- テンプレート見出しの管理メニューから保存済みパターンを削除できる。中央の確認で、実際の勤務は削除されないことを伝える。

ホームの追加ボタンもカレンダーへつなげます。異なる時間を手入力したいときは、右上のプラスからフォームを開きます。選択日の見出しに重複した「追加」は置きません。写真読み取りは通常導線に置きません。

プラスから開く新規フォームの勤務先は、登録済みが1件でも空欄で始めます。「勤務先から選ぶ」には、給料日などを登録した勤務先と、シフト履歴・保存済みテンプレートにある勤務先を同じ一覧にまとめます。選ぶときに保存元の区分を意識する必要はありません。同じ職場のテンプレートが複数あっても勤務先の候補は1件です。履歴だけの勤務先は給料日を勝手に補わず、「給料日を設定」から登録できます。履歴で時給が複数に分かれている場合は1つを推測せず、手入力で確認してもらいます。

削除もゴミ箱を1回押すだけです。すぐ一覧と給与予定に反映し、月表示のすぐ上に、白い背景・控えめな輪郭と影のある「削除しました／元に戻す」カードを5秒表示します。「あと○秒」と短くなるバーを添え、戻せる残り時間が分かるようにしています。削除した件数と残り秒数を同じ行に揃え、バーをその下に長く表示します。「元に戻す」は細い区切りの右側に矢印と文字でまとめ、ナビゲーションの「シフト」見出しは残します。カードの表示・非表示ではカレンダーやテンプレートの位置を動かしません。連続で削除すると最後の削除から5秒を数え直し、表示された件数をまとめて復元できます。元のID・勤務時間・時給・休憩・手当を保持します。

元に戻す期間中は、その勤務パターンをテンプレートから消しません。別のシフトを同じ時間に登録した場合は、復元で勤務が二重にならないよう検証します。ログアウト時には復元候補を消します。

実装は [ShiftsTab.swift](../ShiftManagerApp/ShiftManagerApp/ShiftsTab.swift)。

## ホーム：来月の給与予定を見返す

金額はiOS標準の書体と通常の太さで表示し、ホーム・給与・年収で揃えます。丸い太字や、見出しの数字を等幅にする装飾は使いません。

黒いカードとグラフの見た目を残し、登録したシフトから来月支給される金額を表示します。他タブで閲覧している月には連動させず、今日を基準にした翌月の支給分を使います。

勤務先の締め日・支給日・休日調整で対象勤務を絞り、控除前であることを表示。グラフは給料日ごとの支給予定の累計です。勤務先が未登録なら推測で含めず、設定への案内を出します。実際の手取りと混ぜません。

金額を隠すボタン、次のシフトへの導線、勤務先別の来月の見込みも維持します。残高・生活費の予測やカードの並べ替えは通常画面から外します。

## 給料日：正確な給与を入力 → 年収の残りを見る

給料日のコインアニメーションから、給与明細の課税支給額を入力します。税・保険料を引く前、非課税項目を除いた額を使います。振込額は任意の別項目です。過去の手取り記録を課税支給額として流用しません。

ホームの年収カードは、1〜12月に支給済みの入力金額だけを合計し、本人が設定した年間上限までの残りを表示します。未来の支給日、シフトの見込み、生活スタイルの推測は含めません。同じ勤務先・支給日の編集は既存記録を修正し、二重計上しません。

上限は家族の扶養など本人の条件に合わせて設定します。健康保険の扶養判定は将来の収入見込み等が関係するため、この暦年の残り表示で「安全」とは判定しません。入力金額の根拠：[国税庁・給与所得となるもの](https://www.nta.go.jp/taxes/shiraberu/taxanswer/gensen/2508.htm)、[給与所得](https://www.nta.go.jp/taxes/shiraberu/taxanswer/shotoku/1400.htm)。健康保険の基準との違い：[日本年金機構](https://www.nenkin.go.jp/oshirase/taisetu/jigyosho/2026/202605/0501.html)。

実装は [ContentView.swift](../ShiftManagerApp/ShiftManagerApp/ContentView.swift)、[IncomeWallView.swift](../ShiftManagerApp/ShiftManagerApp/IncomeWallView.swift) の `RecordedIncomeWallCard` と `RecordedIncomeWallDetailView`。以前の詳細な税・年収予測画面は開発履歴として残し、現在の通常導線では使用しません。

## 初回の入力を減らす

勤務先登録は名前・時給・締め日・給料日を中心に表示します。手当・割増・税関連の細かな設定は必要な場合だけ開く構成です。シフト・テンプレートの新規フォームは勤務先を空欄で始め、一覧から選択するか新しく入力します。
